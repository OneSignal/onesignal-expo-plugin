# OneSignal Expo Demo

Reference app for `onesignal-expo-plugin` and `react-native-onesignal`. It showcases SDK features including push notifications, in-app messaging, user management, tags, triggers, outcomes, live activities, and more, using the plugin packed from this repository.

The demo uses package/bundle id `com.onesignal.example`. It needs a native build; Expo Go is not supported.

## Prerequisites

- [Expo environment setup](https://docs.expo.dev/get-started/set-up-your-environment/) for Android and iOS (Android Studio, Xcode, CocoaPods)
- Vite+ (`vp`) and Bun
- An Android emulator or device, and/or a booted iOS simulator

## Setup

Install the plugin's dependencies from the repository root, since setup builds and packs the plugin from there:

```bash
vp install
```

Then, in this directory:

```bash
cp .env.example .env
```

Don't run `vp install` in this directory on a fresh clone. The demo depends on the packed `onesignal-expo-plugin.tgz`, which setup creates, and setup installs the demo's dependencies itself.

Set your OneSignal credentials in `.env`:

```bash
EXPO_PUBLIC_ONESIGNAL_APP_ID=your-onesignal-app-id
EXPO_PUBLIC_ONESIGNAL_API_KEY=your-onesignal-api-key
EXPO_PUBLIC_ONESIGNAL_ANDROID_CHANNEL_ID=
```

- `EXPO_PUBLIC_ONESIGNAL_APP_ID`: falls back to a built-in default App ID when empty.
- `EXPO_PUBLIC_ONESIGNAL_API_KEY`: REST API key, used to update and end live activities. Sending notifications from the demo doesn't need it.
- `EXPO_PUBLIC_ONESIGNAL_ANDROID_CHANNEL_ID`: optional Android notification channel for the sound test notification. Falls back to a built-in default channel.

The OneSignal app needs FCM credentials for Android and APNs credentials for the `com.onesignal.example` bundle ID on iOS.

## Run

```bash
vp run android
vp run ios
```

Each command first runs `setup` (`../setup.sh`), which builds and packs the plugin from the repository root and installs it (and the demo's dependencies) when it changed. It then runs `expo run:android --device` / `expo run:ios --device`, which asks you to pick a device.

`ios/` and `android/` are generated by `expo prebuild` from `app.config.ts` and are mostly gitignored. On a fresh clone, Expo reports the native projects as malformed and offers to reinitialize them. Accept, and it runs prebuild.

After changing `app.config.ts` or plugin config, regenerate the native projects:

```bash
vp run clean
```

iOS signing uses the `appleTeamId` in `app.config.ts`. Simulators work as is; for a physical device, set your own team.

## Other scripts

| Script            | Purpose                                                                      |
| ----------------- | ---------------------------------------------------------------------------- |
| `vp run setup`    | Build, pack, and install the plugin into the demo.                           |
| `vp run clean`    | Run setup, then `expo prebuild --clean` to regenerate `ios/` and `android/`. |
| `vp run start`    | Start the Metro dev server for an already installed build.                   |
| `vp run open:ios` | Open `ios/OneSignalDemo.xcworkspace` in Xcode.                               |

Set `FORCE_SETUP=1` to reinstall the plugin even when the packed tarball is unchanged.

## Firebase Installation ID (Android)

The demo enables `enableFirebaseInstallationId` only when `examples/demo/google-services.json` exists (gitignored). Use one from a Firebase project whose client entry matches `com.onesignal.example`. The demo also forces `firebase-messaging` 25.1.2, which FID registration requires.

```bash
vp exec expo prebuild --platform android --clean
vp exec expo run:android
```

Run prebuild explicitly after adding or changing the file. `expo run:android` skips prebuild because `android/` already exists (the Gradle wrapper is committed), so it would build without FID.

Confirm `firebase_messaging_installation_id_enabled` is `true` in `android/app/src/main/AndroidManifest.xml`. Expo Go is not supported.
